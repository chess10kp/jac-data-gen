# Frontend app eval suite — v1

Generation baseline described in `docs/frontend_app_evals.md`: a fixed ladder
of self-contained frontends (one paragraph spec + behavioral assertions each),
generated by a model and scored headlessly.

## Contents

- `specs.json` — 20 app specs (tiers 0–4), each `{id, tier, name, spec, assertions}`.
- `preds/<model>/<id>/index.html` — generated single-file app (inline CSS/JS,
  no external resources).
- `preds/<model>/<id>/raw.txt` — raw model output.
- `preds/<model>/manifest.jsonl` — per-app status/bytes/tokens.

## Regenerate

```bash
python3 scripts/gen/frontend_apps_generate.py \
  --model ornith-ai/Ornith-1.5-9B \
  --workers 3 --max-tokens 28000   # Featherless caps ctx at 32k and ~4 concurrent req
```

Env: `FEATHERLESS_API_KEY` (or `~/.secrets`), `BASE_URL`, `MODEL`. Existing
outputs are cached; `--force` or `--only <ids>` to regenerate.

## Notes on `ornith-ai/Ornith-1.5-9B` (baseline run 2026-10-09)

- All 20 apps produced parseable single-file HTML; headless Chromium renders
  every one with real DOM content and 0 console errors.
- The model emits a `reasoning` field that counts against `max_tokens`; complex
  specs (notion-lite) can loop in reasoning and never emit content. If
  extraction fails, retry with higher temperature or an assistant prefill
  containing the start of the file (the approach that finally worked).
- Featherless account cap is ~4 concurrent requests; `--workers 3` is safe.
- Non-streamed responses are truncated (malformed JSON) when reasoning grows
  large; use `"stream": true` for big generations.

## Spot-check observations (baseline run)

- `todo-list`: checkbox updates localStorage `done` but does NOT add `.done`
  to the `li` until reload — the "renders but stale state" failure mode.
  Everything else (add/Enter, delete, persistence) verified working via CDP.
